# E5 · Sala integrada y pizarra SVG

## Cambios

- `connection.ts` concentra el transporte del navegador. El hook React y attachLive lo comparten; ya no hay dos implementaciones de reconexión/protocolo.
- `attach.ts` ofrece modo personal sin conexión de sala y modo compartido con el mismo engine. Expone limpieza y suscripción a estado, monta el panel junto al workspace y usa live-slot cuando existe.
- `ui/TeacherPanel.ts` y `ui/StatusChip.ts` son DOM vanilla en Shadow DOM: aceptación/rechazo/expulsión, código/enlace, estado, tema, entrada del alumno, cierre confirmado y reapertura. La fuente de sala no cambia la de la pizarra.
- `/boards/prueba/` es ahora SVG + JS/TS sin React. Expone window.FroebelBoard y permite círculos movibles, lápiz, texto, tamaño, Gemelo, Borrar, Limpiar, Deshacer, imán y modo grande.
- `_plantilla/` y `PORTAR_PIZARRA.md` permiten copiar el contrato. La plantilla funciona sola; su registro como segunda pizarra de sala queda para E6.
- joined añade el nombre del propio alumno únicamente en su conexión autenticada. No se guarda su nombre en almacenamiento del navegador ni se envía a otros alumnos.
- Phosphor Core 2.1.1 se verificó con npm view antes de fijarlo. Se importan SVG oficiales por archivo, sin CDN. No se añadieron servicios externos.

## Límites y siguientes etapas

La imagen del usuario guía la composición y la marca. No se añaden botones falsos para las nueve familias geométricas ni se porta el HTML completo. E6 terminará las pantallas de entrada, su navegación hacia la página SVG y el cambio real entre prueba/_plantilla. app/ no se tocó. Siguen vigentes las consideraciones de migración histórica descritas en E3 antes de desplegar.

No se probaron dispositivos físicos ni un lector de pantalla externo. La API del portapapeles confirmó la escritura, pero su lectura mediante el controlador del navegador no reflejó el contenido; se documenta esa limitación. No se volvió a probar el login real de Supabase ni se hicieron despliegues.

Todo se ejecutó localmente. No hubo push, cambios de facturación, suscripciones, generación de voz ni servicios de pago. E5 termina con commit y espera el OK del usuario para E6.
