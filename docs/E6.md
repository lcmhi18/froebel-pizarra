# E6 — Entradas y navegación entre pizarras

## Resultado

/profesor crea una sala con pizarra inicial, guarda su acceso en localStorage y abre la página SVG independiente. Reutiliza el JWT de la sesión existente de Supabase; el Worker sigue validando usuario, rol y estado. El botón de prueba solo se compila en desarrollo.

/alumno pide código y nombre, permanece en la pantalla de espera y, después de aceptación, navega a la pizarra indicada por el servidor. El UUID privado queda en sessionStorage y se reutiliza al reconectar. Ningún token va en la URL.

El panel del profesor permite cambiar entre prueba y _plantilla con confirmación nativa. El servidor conserva estados independientes, avisa a los editores y entrega el snapshot correspondiente. attachLive corrige una ruta que no coincide con el boardId autorizado. Durante la transición el motor bloquea cambios hasta recibir el snapshot completo. _plantilla sigue siendo una segunda pizarra mínima; no sustituye el HTML completo del usuario.

Las salas recientes se recuperan de los accesos guardados en el mismo navegador. Entrar o reabrir usa el token conservado y respeta la caducidad del servidor. Olvidar un acceso exige confirmación explícita y solo elimina el acceso local, sin cerrar la sala remota.

La reconexión autenticada de un alumno pendiente o activo no consume una segunda cuota de primera admisión de tres segundos. Siguen vigentes la limitación de consultas de Registry, el reemplazo de sesiones duplicadas y las cuotas de reentrada de identidades retiradas.
